# GitHub Pages Setup Guide

This guide explains how your Flutter app is deployed to GitHub Pages and how to troubleshoot common issues.

## 🎯 Current Status

Your repository is now configured to automatically deploy your Flutter web app to GitHub Pages. Here's what happens:

1. **When you merge this PR to `main`**: The GitHub Actions workflow will automatically trigger
2. **The workflow will**: Build your Flutter web app with the correct base path
3. **Deployment**: The built files will be deployed to the `gh-pages` branch
4. **Live Site**: Your app will be available at https://iamSaifulhassan.github.io/bookreadapp/

## 🔧 What Was Fixed

### Problem
GitHub Pages was showing the README content instead of your Flutter app.

### Solution
Added a `.nojekyll` file to the deployment process. This file tells GitHub Pages to serve your Flutter app as-is, without Jekyll processing that can break Flutter apps.

## 📋 How to Deploy

### Automatic Deployment (Recommended)
1. Merge this PR to the `main` or `master` branch
2. The workflow will automatically run
3. Wait 2-5 minutes for the build and deployment to complete
4. Visit https://iamSaifulhassan.github.io/bookreadapp/ to see your app

### Manual Deployment
You can also manually trigger a deployment:

1. Go to the **Actions** tab in your repository
2. Select **"Deploy to GitHub Pages"** workflow
3. Click **"Run workflow"**
4. Select the branch (usually `main`)
5. Click **"Run workflow"**

## 🔍 Checking Deployment Status

### Check Workflow Runs
1. Go to: https://github.com/iamSaifulhassan/bookreadapp/actions
2. Look for the "Deploy to GitHub Pages" workflow
3. Click on a run to see detailed logs
4. Green checkmark ✅ = successful deployment
5. Red X ❌ = failed deployment (check logs for errors)

### Check GitHub Pages Settings
1. Go to: https://github.com/iamSaifulhassan/bookreadapp/settings/pages
2. Verify:
   - **Source**: Deploy from a branch
   - **Branch**: gh-pages
   - **Folder**: / (root)
3. You should see: "Your site is live at https://iamSaifulhassan.github.io/bookreadapp/"

## ⚠️ Troubleshooting

### Issue: Still seeing README instead of the app

**Solution 1: Wait for the first deployment**
- The app hasn't been deployed yet
- Merge this PR to trigger the first deployment
- Wait 5 minutes after merging

**Solution 2: Clear your browser cache**
```
- Press Ctrl+Shift+R (Windows/Linux) or Cmd+Shift+R (Mac)
- Or use incognito/private browsing mode
```

**Solution 3: Check if the workflow ran successfully**
- Go to the Actions tab
- Look for a successful workflow run
- If the workflow failed, check the logs for errors

### Issue: Workflow fails with "Permission denied"

**Solution: Check repository permissions**
1. Go to: https://github.com/iamSaifulhassan/bookreadapp/settings/actions
2. Under "Workflow permissions", select: **Read and write permissions**
3. Click **Save**
4. Re-run the workflow

### Issue: App loads but shows errors

**Possible causes:**
1. **Firebase configuration**: Ensure your Firebase project is set up correctly
2. **Base path**: The app is configured for `/bookreadapp/` - this must match your GitHub Pages URL
3. **CORS issues**: Some Firebase features may need additional configuration for web

## 📝 Important Notes

1. **Base Path**: Your app is configured to run at `/bookreadapp/` (not the root `/`)
   - This matches your GitHub Pages URL structure
   - Don't change this unless you're using a custom domain

2. **Branch Protection**: The workflow deploys to the `gh-pages` branch
   - Don't manually edit the `gh-pages` branch
   - It's automatically generated by the workflow

3. **Firebase**: The app uses Firebase, which requires:
   - Valid Firebase configuration in `lib/auth/firebase_options.dart`
   - Firebase project to be properly set up
   - Web app to be registered in your Firebase project

4. **First Load**: The first time you visit the app, it may take a few seconds to load
   - This is normal for Flutter web apps
   - Subsequent loads will be faster due to caching
